## 1. 项目背景与目标

公司内部存在大量生产设备（缝纫、裁剪、包装、技术等），此前以 Excel `设备借出总账.xlsx` 手工登记设备与借出情况，存在以下问题：

- 无法快速回答"某个编号的设备现在在哪、什么时候交出去的、历史经过哪些班组/公司"；
- 台账数量与编号、借出台数与编号完全依赖人工一致性维护；
- 数据无归还记录、无逾期概念、无历史追溯，只能靠翻阅表格。

**系统目标**：交付一个 Windows 单机运行的"设备资产与流转管理系统"，以**单个设备编号为唯一身份**管理设备生命周期与每一次流转，让使用者随时回答 8 个核心问题（见 §4）。

**第一版数据来源**：`设备借出总账.xlsx`（一次性初始化导入，之后禁止把 Excel 当数据库）。

## 2. 使用场景与部署约束

| 项 | 要求 |
|---|---|
| 运行环境 | Windows 7 SP1（64 位，兼容目标）+ Windows 10 / 11（决策基线 11） |
| 启动方式 | 双击 `equipment.exe` → 自动启动本地服务 → 自动打开 `http://localhost:8080` |
| 浏览器 | Win10/11 任意现代浏览器；**Win7 需 Chrome 109 或 Firefox ESR 115**（交付物随附 Chrome 109 离线安装包与说明）；不支持 IE |
| 数据存储 | 本地 SQLite：`equipment.db` |
| 备份 | `backup/`（启动自动备份 + 手动备份 + 恢复，默认保留最近 30 份） |
| 网络 | 单机离线，不依赖互联网、服务器、云 |
| 技术栈 | 后端 Go(Gin+GORM+SQLite, 纯 Go 无 CGO, 交付工具链 Go ≤ 1.20)；前端 React+TS+Vite+AntD+ECharts（按 Chrome 109 能力构建） |

## 3. 用户与角色

系统无登录体系（决策基线 5）：单机单使用者场景。
操作人（operator）通过操作表单输入并记忆最近使用。

---

## 4. 核心业务问题（验收锚点）

系统必须能够立即回答：

1. 设备 6061 现在在哪里？→ 当前位置（仓库/班组/外借方）
2. 6061 什么时候到当前位置（交付时间）？→ 最近一次流转到当前位置的时间（决策 8）
3. 6061 以前在哪？→ 完整流转历史（时间线）
4. 哪些设备在库？→ 状态筛选=在库
5. 哪些设备在某个班组？→ 状态/班组筛选
6. 哪些设备外借了？→ 状态筛选=外借
7. 借给谁了？→ 外借方
8. 借了多久 / 是否逾期？→ 外借日期、预计归还日期、实际归还日期（逾期判定见决策 9）

## 5. 功能需求

### FR-1 Dashboard（首页）
- 统计卡片：设备总数、在库、班组使用、外借、维修、报废（按状态实时统计）。
- 图表（ECharts）：状态分布、各班组设备数、各类别设备数。
- 列表：最近流转、最近归还、当前外借、**逾期未还（标红）**。

### FR-2 设备台账
- 列表列：设备编号、名称、型号、类别、状态（中文+色点）、当前位置、当前班组/外借方、最后更新。
- 检索：编号/名称/型号 关键字（含前缀/包含）、类别筛选、状态筛选、班组筛选、分页。
- 设备详情（点击编号）：基本信息 + 当前状态/位置/班组/交付时间 + **完整流转时间线**。

### FR-3 设备新增 / 编辑 / 更正
- 新增设备（录入编号/名称/型号/类别/备注）。
- 编辑名称、型号、类别、备注（可改）；**设备编号不可修改（决策 13）**。
- 编号录错：走"受限更正"（填写原因、留 audit 记录）或报废重建，无直接改号入口。

### FR-4 设备流转（核心）
页面按钮化操作，每次流转 = 更新当前状态 + 写 transaction（同一事务）：
入库、出库给班组、班组转交、外借、外借归还、送修、维修完成、报废。
约束与状态机见 `docs/state-machine.md`。

### FR-5 外借管理（外借单）
- 独立外借单（borrow_record），一设备一单（决策 2）；支持批量外借（多台同公司/日期逐台成单）。
- 列表：设备编号、名称、外借方、外借日期、预计归还日期、实际归还日期、状态（外借中/已归还/逾期）。
- 操作：外借、归还（逐台，归还回仓库，决策 3）、延期（修改预计归还日期）、查询。
- 逾期醒目提示（决策 9：过预计归还日且未归还即逾期）。

### FR-6 班组管理
新增/改名/停用班组；停用后不再可选但历史保留。历史记录显示流转当时班组名（名称快照，决策 14）。

### FR-7 外借方管理
新增/改名/改联系人电话/停用外借方（公司）；下拉选择；历史保留快照（决策 14）。

### FR-8 类别字典（决策 12）
系统设置中维护类别字典（如"裁剪设备"），设备录入与筛选从字典取值；导入遇新类别自动归入。

### FR-9 Excel 初始化导入
流程：选文件 → 解析 → 预览 → 校验 → 错误展示 → 用户确认 → 写入 SQLite。
导入报告：总记录/成功/跳过/重复/异常/无编号（含明细可导出）。
规则详见 `docs/import-rules.md`；危险操作（覆盖/清空）一律二次确认。

### FR-10 数据备份 / 恢复
启动自动备份、手动备份、恢复（二次确认）、保留最近 30 份、恢复前自动再备份当前库。

### FR-11 系统设置
- 类别字典、默认备份保留份数、端口（config.yaml）等少量项。
- 操作人最近记忆（前端本地）。

### FR-12 Excel 导出
台账当前列表（含筛选结果）导出 Excel（Phase 5）。

## 6. 数据与一致性原则（硬约束）

1. 一个设备编号对应一个设备实体（原则一），但**源数据存在同号重复疑点** → 导入时阻断处理，不默认合并（见 data-analysis §6、import-rules §5）。
2. 当前状态（equipment）与历史记录（transaction）分离（原则二）。
3. 任何状态变化 = 更新当前状态 + 新增 transaction（原则三，同事务）。
4. 流转历史禁止删除；敏感操作（删除、覆盖、清空、恢复、导入、受限更正）全部二次确认并记 audit。
5. 设备禁止物理删除，只能流转至报废（决策 6）。
6. Excel 仅用于首次初始化；正式数据只存 SQLite。

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 正确性 | 状态机白名单校验；事务完整性（失败不留脏数据） |
| 安全 | 无 SQL 拼接、输入校验、上传文件校验、危险操作确认、敏感信息不硬编码 |
| 性能 | 数据规模 ≤ 万级设备，常规查询 < 1s，单机场景无并发压力 |
| 兼容 | Win7 SP1 x64 + Chrome109/FF115 实机验证；Go1.20 交付工具链 |
| 可维护 | 分层架构、统一错误格式、REST 语义化、Conventional Commits |
| 备份安全 | 每次恢复前自动备份当前库；备份文件带日期 |

---

## 8. 范围外（第一版不做）

- 新增状态类型/新流转动作的自定义（白名单锁死，需代码升级）；
- 页面可视化装修/自定义报表；
- 多用户、权限、登录；
- 多仓库/多库存位管理（若"南库"等概念必须支持，见 data-analysis 待确认 W-12 后追加）；
- 网络版 / 多客户端并发。

- Phase 1：骨架可 `go build` 出 exe 并在 8080 出页面；

- Phase 5：Dashboard/导出/备份/恢复可用；
- Phase 6：Win7 SP1 与 Win10/11 双环境全链路回归通过，交付 `equipment.exe`+Chrome109 离线包+使用说明。
