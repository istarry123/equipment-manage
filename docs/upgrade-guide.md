# 设备资产与流转管理系统 — 版本升级说明

**本次升级：v1.3.0 → v1.4.0**
适用场景：**客户电脑上已经在使用本系统、并且已经导入了真实数据**，现在要把程序换成新版本。

---

## 0. 先读这三条（避免数据事故）

| # | 铁律 | 原因 |
|---|---|---|
| 1 | **只替换 `equipment.exe`**，绝不整体覆盖程序目录 | 交付包里有一个 `equipment.db`（那是给"全新安装"用的数据文件）。整体拷贝会**覆盖客户自己的数据**——客户升级后新录入的内容会全部丢失 |
| 2 | **升级前必须先关闭程序**（控制台窗口关掉） | 程序运行中：`equipment.db` 被独占锁定、`equipment.exe` 也无法替换。升级脚本检测到程序在运行会直接拒绝执行 |
| 3 | **不要动 `config.yaml`** | 里面是本机端口等设置。脚本不会碰它；手工操作时也不要覆盖 |

需要保留（**一律不要覆盖**）的文件与目录：

| 保留 | 内容 |
|---|---|
| `equipment.db` | 全部设备、流转、外借数据 |
| `backup/` | 历史备份与升级前快照 |
| `config.yaml` | 本机设置（端口等） |
| `logs/` | 运行日志 |

---

## 1. 本次升级是否安全？—— 已实测，不动数据

本系统把"程序"和"数据"分开存放，所以升级只换程序。

**v1.4.0 是界面与交互更新，不含数据库结构变更：**

- `v1.3.0 → v1.4.0` 后端**只改了版本号字符串**，数据库迁移文件（`internal/database`）**零改动**；
- 客户库的 schema 版本保持 `user_version = 4` 不变，程序启动时的迁移检查是**幂等空操作**（不会改数据）。

**升级演练实测结果**（用 v1.3.0 的程序 + 一份数据库副本模拟客户机器，完整跑了一遍升级）：

| 核对项 | 结果 |
|---|---|
| 升级前后 `equipment.db` 的 SHA256 | **逐字节一致** |
| 设备数据 | 升级前 `总数=2148，在库=1815，外借=333` → 升级后**完全相同** |
| `config.yaml`（端口设置） | 未被改动 |
| 程序版本号 | `1.3.0` → `1.4.0` |

> **例外情况**：如果客户当前版本**早于 v1.1**（例如 v1.0.0 / v1.1 之前），升级后首次启动**会执行数据库迁移**（程序会自动先备份）。这种跨大版本的升级建议先在备用机上用数据副本试跑一次。

## 2. 准备：本次要用的文件

从交付包 `update-only/` 取这三个文件（**只有这三个**）：

```
equipment.exe      新版程序（v1.4.0）
update-app.ps1     升级脚本
user-guide.md      新版用户手册（可选）
```

把它们放到客户电脑的一个临时文件夹，例如 `C:\update`。

> 怎么找到"程序目录"？在客户电脑上右键 `equipment.exe` 的快捷方式（或程序本身）→「打开文件所在的位置」，地址栏显示的目录就是 `-TargetDir` 要填的值，例如 `D:\equipment`。

## 3. 升级步骤（推荐：用升级脚本）

在客户电脑上打开 PowerShell，依次执行：

```powershell
# 第 1 步：确认程序已关闭（无输出 = 已关闭）
Get-Process equipment -ErrorAction SilentlyContinue

# 第 2 步：执行升级（把 D:\equipment 换成客户实际程序目录）
powershell -ExecutionPolicy Bypass -File C:\update\update-app.ps1 -TargetDir "D:\equipment"
```

脚本会依次完成：

1. 校验目录正确（目录里必须有 `equipment.db`，防止选错目录）；
2. 确认程序没有在运行；
3. 把当前数据库备份为 `backup\pre-update-<时间>.db`；
4. 把**旧程序**备份为 `backup\equipment-before-update-<时间>.exe`；
5. 只替换 `equipment.exe` 与 `user-guide.md`；
6. 打印目录核对结果（`equipment.db` 的大小与修改时间应与升级前**完全一致**）。

脚本正常输出示例：

```
== 设备管理系统 程序更新（保留数据）==
[1/3] 已备份数据库：D:\equipment\backup\pre-update-2026-09-12_150745.db
       已备份旧程序：D:\equipment\backup\equipment-before-update-2026-09-12_150745.exe（回退用）
[2/3] 已更新 equipment.exe
       已更新 user-guide.md
[3/3] 核对目标目录：
       equipment.exe      28448256 字节
       equipment.db       1503232 字节     ← 大小与修改时间应保持升级前的值
       config.yaml        67 字节
更新完成。
```

## 4. 升级后的核对（务必做）

### 4.1 看界面

1. 双击 `equipment.exe`（会自动打开浏览器到 `http://localhost:<端口>`，默认 8080）；
2. **左上角版本号应为 `v1.4.0`**；
3. 打开「设备台账」，**总数与升级前一致**。

### 4.2 数值核对（推荐，比肉眼点表格可靠）

升级前先跑一次下面这条命令记下结果，升级后再跑一次对比：

```powershell
$d = Invoke-RestMethod http://localhost:8080/api/dashboard
"总数=$($d.total)  " + (($d.by_status | ForEach-Object { "$($_.status)=$($_.count)" }) -join ' ')
```

演练实测（升级前后应完全一致）：

```
总数=2148  IN_STOCK=1815 IN_TEAM=0 BORROWED=333 MAINTENANCE=0 SCRAPPED=0 OTHER=0
```

> 端口若改过，把 `8080` 换成客户 `config.yaml` 里的 `port` 值。

### 4.3 本次升级带来的变化（供核对"确实换新了"）

| 变化 | 怎么看 |
|---|---|
| **界面默认深色** | 打开就是深色；顶栏右上角按钮可切浅色 |
| **页面地址可直达、F5 刷新不丢页** | 地址栏输入 `/equipment`、`/import-detail` 等可直接打开，刷新后仍在当前页 |
| **侧栏可折叠** | 左侧菜单左下角的折叠条 |
| **编号等宽字体 / 表头吸顶** | 台账列表向下滚动时表头固定 |
| **清空重导需输入 `RESET` 确认** | 「数据导入」页的危险操作门槛提高 |
| 业务行为 | **完全未变**（状态、流转、导入、对账、导出、备份、分页口径） |

## 5. 如果升级后发现问题：回退方法

**先关闭程序**，然后按需选择：

### 5.1 只回退程序（最常见，数据本来就没变）

把 `backup\equipment-before-update-<时间>.exe` 改名为 `equipment.exe`，覆盖回程序目录即可。

> 实测有效：回退后版本号回到 `1.3.0`，数据完好。

### 5.2 连数据一起回退（正常升级用不到）

把 `backup\pre-update-<时间>.db` 复制成 `equipment.db` 覆盖（同样要先关程序）；
或启动程序后用「数据备份」页选择该快照恢复。

---

## 6. 备选方案：手工替换（脚本无法运行时）

脚本跑不起来（如 PowerShell 被策略限制）时，可手工操作——**同样只换 exe**：

1. 关闭程序；
2. 建议先在程序内「数据备份」页点一次**手动备份**；
3. 把新 `equipment.exe` 复制到程序目录，提示"是否替换"选**是**；
4. 启动程序，按第 4 节核对。

手工方式没有自动备份，所以第 2 步的手动备份**不要跳过**。

---

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 脚本报「检测到程序正在运行」 | 客户机上有 `equipment.exe` 还在跑。关掉控制台窗口；或任务管理器结束 `equipment.exe` 后重试 |
| 脚本报「目标目录未见 equipment.db，可能选错了目录」 | `-TargetDir` 填错了。必须是**实际存放 `equipment.db` 的那个目录** |
| 提示无法加载脚本 / 禁止运行脚本 | 用第 3 节给出的完整命令（带 `-ExecutionPolicy Bypass`）。若仍被拦，执行 `Unblock-File C:\update\update-app.ps1` 后重试 |
| 替换 exe 时提示文件被占用 | 程序还在运行（或后台残留进程）。结束 `equipment.exe` 进程后重试 |
| 浏览器打不开页面 | 确认程序控制台窗口没有报错；确认端口未被占用（`config.yaml` 可改端口） |
| 新版打开后页面样式没变化 | 浏览器缓存。按 `Ctrl+F5` 强制刷新，或换无痕窗口打开 |
