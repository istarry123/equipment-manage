# 设备资产与流转管理系统 — 用户手册（v1.1.0）

> 适用：Windows 7 SP1（64 位）/ Windows 10 / Windows 11。单机使用，无需联网。
> 配套：`equipment.exe`、`config.yaml`（可自行生成）、`backup/`、`logs/`、`docs/user-guide.md`。
> v1.1（2026-09-09）：设备身份重构 —— 编号可重复/可空，系统以内部记录区分设备并以「显示编号」统一展示；导入改为「解析预览 → 人工审阅（REVIEW / 疑似在借）→ 导入 → 对账」流程，支持历史日期补录与清空重导。

---

## 1. 运行环境与浏览器（重要）

| 系统 | 要求 |
|---|---|
| Windows 10/11 | 任意现代浏览器（Edge/Chrome/Firefox） |
| **Windows 7 SP1 (x64)** | 必须使用 **Chrome 109** 或 **Firefox ESR 115**；**IE 不支持** |

Win7 浏览器获取（需在有网的机器下载后拷贝）：
- Chrome 109 历史离线安装包：在可联网电脑打开
  `https://dl.google.com/chrome/install/109.0.5414.120/chrome_installer.exe` 下载，
  拷到本机双击安装（需管理员）；或使用 Firefox ESR 115。
- 若无法访问 Google，可联系 IT 从内网软件源获取同版本离线包放入 `install/` 目录备用。

## 2. 启动与首次使用

1. 双击 `equipment.exe`（控制台窗口保持开启属正常；关闭窗口=退出程序）。
2. 自动打开浏览器 `http://localhost:8080`（若未自动打开，手动访问该地址）。
3. 首次启动自动完成：建库（equipment.db）→ 建表（含历史索引）→ **自动备份**到 `backup/` → 就绪。
4. 首次数据：进入左侧 **数据导入**，选择公司提供《设备借出总账.xlsx》→ **解析预览**（含设备级清单、校验问题、REVIEW 项、疑似在借）→ **人工审阅** → **确认导入** → **数据对账**。

> 说明（v1.1）：导入走「解析 → 预览 → 审阅 → 导入 → 对账」五步。
> - **重复编号不再阻断**：同一编号可对应多台真机，预览按台展开（编号原样保留，可含中文符号）；无法自动判断的内容进 **REVIEW** 待人工确认，确认前该部分不会导入，**绝不静默丢弃**。
> - **疑似在借**：Excel 中最后一次借出无归还证据的设备会列入「疑似在借」，由用户勾选确认当前仍在外借（外部公司）后，随导入一并置为外借状态；无法确认的保持【在库】。默认全部设备以【在库】导入。
> - **清空重导**：系统正式使用后再用 Excel 重导 = 危险操作，需在导入页先执行「**清空重导**」（自动备份 → 清空业务数据 → 重新导入），字典/设置/审计保留。
> - **数据对账**：导入后点击「执行对账」，把 Excel 可导入设备与数据库该批次设备逐台比对，PASS=一致；FAIL=给出缺失/多出清单。
> - 业务正式使用后**不要再用 Excel 改数据**（Excel 仅一次性初始化数据源）。

## 3. 页面功能速览

| 菜单 | 用途 |
|---|---|
| Dashboard | 总数/状态/班组/类别统计、最近流转、外借与逾期提醒 |
| 设备台账 | 搜索(编号/名称/型号，支持「显示编号」)、类别/状态/班组筛选、新增/编辑、双击行看详情；**导出设备台账 / 导出流转情况** |
| **班组设备** | 按「班组 → 设备类别 → 设备」查看各班组当前使用设备；未分配设备（在库/外借/维修）单列便于排查；点设备编号进入既有设备详情 |
| 设备流转 | 与设备台账同入口：详情内按状态提供 出库/转交/入库/外借/归还/送修/维修完成/报废 |
| 外借管理 | 外借单列表（逾期标红）、归还、延期；外借方(公司)维护；归还/延期支持填写历史日期 |
| 班组管理 | 班组/内部单位（含"双发"分厂）增改、停用、**删除（仅未被占用且无历史引用时）** |
| 数据导入 | Excel 解析预览 / REVIEW 审阅 / 疑似在借确认 / 导入 / 数据对账；危险入口「清空重导」 |
| 数据备份 | 手动备份、查看备份、恢复（需输入 RESTORE 确认） |
| 系统设置 | 类别字典新增/**删除（未被设备引用时）**、系统信息 |

每个操作都要求填写**操作人**（记住最近一次），并在设备详情生成可追溯的**流转时间线**。

### 显示编号（v1.1，全站统一）

- 真实设备编号允许**重复**（多台真机同号）或**为空**（无编号设备）；设备身份以系统内部记录区分。
- 页面/导出统一展示后端计算的**显示编号**，规则：
  - 有编号且**同号多台** → `6041（1）`、`6041（2）`…；同号仅一台 → 直接 `6041`；
  - **无编号**设备恒带序号 → 按 `型号（1）`，型号为空则 `名称（1）`，再空则 `未编号设备（1）`。
- 搜索框直接输入显示编号（含 `（n）`）或基础编号均能命中对应设备。
- 设备编号本身不允许直接修改；录错走「受限更正」（填原因，记录审计）。

### 班组设备（视图说明）

- **用途**：管理人员快速回答“A班现在用了哪些设备？”——页面按 **班组 → 设备类别 → 设备** 三级分组展示。
- **归属来源**：当前班组取 `equipment.current_team_id`，当前状态取 `equipment.status`（`IN_TEAM` 才计入班组分组）；不扫描历史记录推断归属。
- **未分配设备**：`current_team_id` 为空的设备（在库/外借/维修等）单独成组展示，便于发现未归队设备；外借设备带“外借”状态标签，不会误显示为某班组在用。
- **与流转的关系**：设备在“设备台账 → 详情 → 出库/转交”后，本视图即时反映；历史记录保持完整不受影响。

## 4. 数据与历史

- 数据存 `equipment.db`（请勿手工编辑）。
- **任何一次流转 = 更新当前状态 + 写一条历史**；历史永久保留、界面不提供删除。
- 设备编号一旦确定不可直接修改；录错走"受限更正"（填原因，记录审计）。
- 班组/外借方改名或停用不影响历史（历史记录当时名称）。
- **历史日期（v1.1）**：手工外借/归还（及其他流转）弹窗可填写**发生日期/实际归还日期**——用于补录历史借出归还；不填默认今天，不允许填未来日期。
- **设备身份（v1.1）**：同一编号可有**多台真机**（各自独立记录、独立流转、独立历史）；无编号设备同样建档。Excel 导入仅作为一次性初始化来源，导入后系统内一切变更都在页面完成。

## 5. 备份与恢复

- 程序**每次启动自动备份**，也可在"数据备份"页手动备份；默认保留最近 30 份。
- 恢复是危险操作：**系统会先自动备份当前库（安全快照）**，替换后即回到该备份时的状态。
- 备份文件在 `backup/`，形如 `equipment-2026-09-08_104514.db`；`pre-restore-*`/`equipment-*_1.db` 为恢复前安全快照，**不要手工删除**最新的那几份。

## 6. 常见问题（FAQ）

**Q1 双击后"端口 8080 被占用"？**
```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select OwningProcess
Get-Process equipment | Stop-Process -Force   # 关掉旧的程序实例
```
或改 `config.yaml` 的 `port`（如 9090）后重启。

**Q2 页面白屏/不显示？**
先关闭旧实例再启动；浏览器按 Ctrl+F5 强刷。若仍白屏，F12→Console 第一条报错发给维护人员。
（已修复历史问题：空库时统计字段为 null 导致白屏。）

**Q3 我想改设备信息？**
名称/型号/类别/备注：设备详情→编辑；编号：详情→受限更正（需原因）。状态只能在库/班组/外借等之间流转，不能直接"改"状态。

**Q4 为什么看到相同编号（如 `6041`）的多台设备？**
真实 Excel 中同一编号可能对应多台真机（录入习惯或不同设备同号）。v1.1 起系统按台建档，用显示编号 `6041（1）`、`6041（2）`… 区分；每台独立流转、独立历史，操作时按行选择即可，不会混淆。

**Q5 无编号设备怎么区分与搜索？**
无编号设备同样逐台建档，显示编号恒带序号（`型号（1）`→`名称（1）`→`未编号设备（1）`）。台账搜索输入显示编号或名称/型号均可命中。

**Q6 导入时提示 REVIEW 未确认，无法导入？**
导入预览中的 REVIEW 项是需要人工判断的异常内容（如无法可靠解析的借出记录）。请逐条查看并在预览中确认/处理后才能导入——系统宁可保留待确认，也**不会静默丢弃**任何设备或数据。

**Q7 系统已正式使用，还能用新 Excel 重导吗？**
可以，但属于危险操作：在「数据导入」页点「清空重导」，系统会先**自动备份**当前库，再清空业务数据（字典/审计历史保留），随后按「预览→审阅→导入→对账」重新导入。需要回退时可从「数据备份」恢复。

**Q8 导入后的"数据对账"是什么？**
把 Excel 中可导入的设备与数据库该批次设备逐台比对。PASS=完全一致；FAIL=页面列出缺失/多出的设备清单，便于核对修正，防止"导入成功但少了台数"。

**Q9 这台电脑坏了/换电脑？**
把整个程序目录拷贝到新机器（含 equipment.db 与 backup/）双击即可，数据库自包含。

**Q10 还有哪些事需要开发人员？**
新增"状态类型/流转动作"、加页面/报表/字段、升级依赖 —— 属于版本升级；日常改数据全部在页面完成。

## 7. 防火墙与安全

- 程序只监听 `127.0.0.1`（仅本机），不会对外网开放，通常**不会触发防火墙询问**。
- 若系统仍询问：允许即可（仅本机回环）。
- 单机离线使用，无账号体系；请通过文件系统权限管理使用者。

## 8. 卸载/数据导出

- 卸载 = 删除整个程序目录（如需保留数据先复制 equipment.db 与 backup/）。
- 台账可在"设备台账"页筛选后从 API 导出：`http://localhost:8080/api/export/equipment`（下载 .xlsx，含当前筛选；v1.1 起首列为**显示编号**，其后保留原始设备编号列）。

### 设备流转情况导出（v1.2）

- 入口：**设备台账** 页右上角「**导出流转情况**」按钮（旁有「导出设备台账」按钮，保留原有台账导出）。
- 弹窗可设置：**班组 / 状态 / 外借公司** 筛选（默认全部）、**数据范围**（当前 + 历史 / 当前设备 / 流转历史，默认「当前 + 历史」）、**包含统计汇总**（默认勾选）。
- 生成一个 Excel（`设备流转情况_YYYY-MM-DD.xlsx`），含三个工作表：
  - **当前流转情况**：每台真实设备一行（编号可重复的设备用 `6041（1）（2）…` 区分，无编号设备用 `型号（1）…`）；含显示编号、原始编号、班组、状态、所在位置、当前外借公司/外借日期、备注。
  - **流转历史**：每条流转一行，按时间倒序；含原位置 → 新位置、班组、外借公司、操作备注。
  - **统计汇总**：导出时间 + 按状态 / 按班组 / 按外借公司 三组数量统计。
- 筛选条件同时作用于三个工作表：例如选「外借公司 = 莒县双发」，Sheet1 只列当前借给莒县双发的设备，Sheet2 只列这些设备的历史，Sheet3 统计范围一致。
- 编号一律按**文本**导出（`001` 不会被 Excel 变成 `1`，中文编号原样保留）；设备ID列默认隐藏，仅用于核对。
- 数据以数据库为准（当前状态来自 equipment，历史来自流转记录），**不重读原始 Excel**；每次导出会记录一条审计（`EXPORT_EQUIPMENT_FLOW`，含筛选条件与导出数量）。

## 9. 版本升级（只换程序，保留数据）

> 已有数据的目标电脑升级时，**绝对不要整体覆盖程序目录**——那会用新版压缩包里的空库覆盖你的真实数据。

程序文件与数据文件是分开的，升级只需替换 **`equipment.exe`**（可选连 `user-guide.md` 一起），以下文件/目录**一律不要覆盖**：

| 保留（不要动）| 说明 |
|---|---|
| `equipment.db` | 全部设备与流转数据 |
| `backup/` | 历史备份（含升级前快照）|
| `config.yaml` | 端口等本机设置 |
| `logs/` | 运行日志 |

### 方法 A：手动替换（最简单）

1. 先关闭目标电脑上的 `equipment.exe`（控制台窗口关闭 = 退出程序）。
2. 建议先备份：把 `equipment.db` 复制一份到别处（或程序内「数据备份」页点手动备份）。
3. 把新版 `equipment.exe`（可连 `user-guide.md`）复制到目标电脑的程序目录，**覆盖同名文件**；提示"是否替换"选**是**。
4. 启动 `equipment.exe`，确认左上角版本号为 **v1.2.0**，且设备台账数量与升级前一致。

### 方法 B：用更新脚本（自动备份 + 只替换程序）

在目标电脑上，把 `update-app.ps1` 与新版 `equipment.exe` 放在同一个文件夹（如桌面的 `update` 文件夹），然后：

```powershell
powershell -ExecutionPolicy Bypass -File update-app.ps1 -TargetDir "D:\equipment"
```

（把 `D:\equipment` 换成目标电脑上实际运行程序的目录）

脚本会：校验目录是否正确 → 拒绝在程序运行时更新 → 自动把当前 `equipment.db` 备份到 `backup\pre-update-<时间>.db` → 只替换 `equipment.exe` 与 `user-guide.md` → 打印核对结果。数据文件不受影响。

> 升级后如发现异常，可把 `backup\pre-update-*.db` 复制回 `equipment.db`（先关闭程序）回到升级前状态；或用「数据备份」页恢复。
