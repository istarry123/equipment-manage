# Excel 导入规则 import-rules.md

> 文档编号：DSH-EQ-IM · 版本：v0.1.0-phase0 · 日期：2026-09-07
> 输入：`设备借出总账.xlsx`（原文件，**导入过程只读**）；结构详见 `docs/data-analysis.md`。
> 目标：把 Excel 结构化数据安全导入 SQLite，禁止未校验直写、禁止猜测字段含义（W-1…W-15 未确认前不得放行对应数据）。

---

## 1. 导入范围与策略（分两层，防错优先）

### Tier 1：设备台账（必做，安全）
仅导入"设备主块（A–F）"→ category/equipment（每块按 D 数量生成实体）。

### Tier 2：借出历史（受限；W-2 已答复，2026-09-08 决策 15）

Excel 无归还列 → 不能从文件判定"当前哪些设备仍在外"。**用户已确认采用方案 A**：

- 方案 A（已定）：Tier 1 只建台账（全部初始"在库"+IMPORT_INIT）；借出历史**不自动导入当前状态**，由用户根据实际在借情况在系统内**手动补录**外借/流转，保真不造假；
- 方案 B / 方案 C（已弃，不再作为导入选项；如未来需要历史时间线还原可另行评估）。

> 状态：Tier 1 为本阶段（Phase 2）实现范围；Tier 2 无自动导入。

## 2. 解析规则（块级）

0. **模板校验（前置 BLOCK，2026-09-11 Phase 1）**：R2 表头必须与导入模板 A–K **逐列一致**（类别/设备名称/设备型号/台账数量/财务数量/台账设备编号/时间/公司/台数/借出设备编号/备注）。不符即返回 `ErrTemplateMismatch` 拒绝解析，错误信息回显 R2 实际内容与 R1 标题行，便于判断"版式不对"还是"表头挪了行"——绝不在错误的列语义下继续解析。事故背景：`工作簿1.xlsx`（到达时间/外借方/数量/设备编号）被按总账模板硬解析，D 列"设备编号"当作"台账数量" → 预览 5,693,048 台。
1. 定位表头 R2（列 A–K 语义固定）；R1/R467/空行/合并间隙行跳过。
2. **设备块识别**：以 B（名称）纵向合并区间或单行实体为块边界（结合 A 合并区与 B/C 合并区间；实现在导入器内按"B 单元格非空行"起块、直到下一块首行）。
3. 块内字段回填：类别（A 合并值）、名称（B）、型号（C）、D/E 取块首（D 为合并总台数，E 为财务段；块内如有多个 E 段则累加做校验）。
4. F（编号）：按空白（空格/换行/全角空格）切分为 token 清单；逐 token trim；
   - `无编号` → 整块无编号设备（数量=D，不产编号行）；
   - token 含字母/数字混合 → 视为真实编号原样保留（不转数字）；
   - token 含括号注释（如 R165/R197/R198/R199）→ 剥离注释保留编号本体，注释存入该设备 remark（W-7 默认）；
   - 首尾多余空白丢弃；行尾续写跨行合并为块的完整清单。
5. G/H/I/J/K（借出事件，Tier 2 使用）：同一行 G 非空=事件首行；I 台数、J 编号 token（规则同 F）；事件跨行续写时（本行 I 与 J 计数不一致但下行 J 续写）按"从该行起直到下一事件首行前的连续 J 行"合并为一个事件。
6. 日期解析：`YYYY.M.D`（M/D 可为 1~2 位）统一为 SQLite ISO；`2018.4`（W-11）缺日 → 报告 WARN 并默认补 1 日或整行待确认（默认补 1 日仅当用户勾选）。
7. 文字规范化：入库字段 trim；B/C 全半角括号保留原文；不主动归并近义名称（W-9）。

## 3. 字典构建

- 类别（A）：识别 4 个明确类别（裁剪设备/缝纫设备/包装设备/技术设备）→ 自动建 category；`买发网厂/买华诺/买针织厂`（R344–R380）与 R429–466 无类别行 → **按 W-1 结果处理**（未确认前归类为待确认类别并标记，绝不静默归并）。
- 外借方（H，19 个名称）：**W-5 已定（决策 15）** —— 名称含「双发」的 4 个内部单位（莒县双发、双发分厂（龙山贸易/华锦/夏津））属**内部调拨**，建 **team（内部单位）字典**而非 borrower；其余 15 个公司建 borrower（name UNIQUE，重复命中即复用）；联系人/电话留空（源无）。Tier 1 不自动落这两个字典（初始全在库，由后续操作按需创建）。
- 班组/内部单位：Tier 1 不自动创建（W-2 方案 A：初始均在库）。
- 无编号设备：equipment_no=NULL，生成 `internal_code=EQ-%06d`（决策 6 与章程 §14：不伪造财务编号）。

## 5. 导入流程（UI 五步，章程 Phase 2）

```text
1) 选择 Excel（本地文件，仅读）
2) 解析（后台执行 §2/§3）
3) 数据预览（块列表/实体样例/字典预览；差异高亮）
4) 校验报告（V1–V10 结果 + 异常明细表，可导出）
5) 用户确认（危险操作二次确认）→ 单事务写入 SQLite → 导入报告
```

**导入报告指标**（章程/主 Prompt 要求）：总记录 / 成功 / 跳过 / 重复 / 异常 / 无编号，另附：
- 设备块总数、设备实体总数（按 D）、类别数、外借方数；
- BLOCK/WARN 明细（可导出 Excel/CSV）；
- 生成的 internal_code 段（EQ-000001…）。

## 6. 初始现状固化（决策 7）

- Tier 1 导入成功后，为每条设备写一条 `transaction(action=IMPORT_INIT, from=初始, to=IN_STOCK, occurred_at=导入日或Excel时间(推荐导入日统一), operator=系统导入, remark=来源行号Rxx)` —— 历史从第一天完整可追溯；
- 若按 W-2 方案 C 提供"当前在借清单"，另为对应设备写 `BORROW` 事件（借出时间用清单日期）；
- **幂等与覆盖防护**：仅允许"空库"或"已导入同文件版本号"前提下执行全量导入；已有业务数据时禁止覆盖导入（数据安全铁律 6/危险操作确认）；如确需重导，走"备份→清空(二次确认+audit)→导入"专门流程（Phase 2 设计）。

## 7. 导入实现约束（技术）

- Go 侧 xlsx 解析：锁定 Go1.20 兼容版本 excelize（构建矩阵验证）；大文件(≤10MB)无压力；
- 解析不依赖 Excel 安装、不联网；
- 入库使用单事务；任何 BLOCK 即整体中止并回滚，保证无脏数据；
- 错误信息给出**行号 + 块名 + 具体值**，便于用户回表核对。

### v1.1 导入落库（Phase 4，2026-09-09）

- 单事务写库：import_batch（批次）→ 类别 → 设备行（编号每 token 一台 / 无编号逐台展开）→ 每台 IMPORT_INIT → 回填批次计数 → 事务内 RenumberAllSeq 分配 equipment_seq → audit。
- 设备带 `import_batch_id` 与 `source_key`（如 `R141-R193#N5` / `#U2`）：来源可追踪、支撑 Reconciliation（Phase 11）。
- 幂等：同文件（source_hash 一致）已成功导入 → `ErrBatchImported` 拒绝；非空库无同批次 → `ErrDBNotEmpty`。清空重导为专门危险流程（Phase 10，先备份）。

### v1.1 J 列借出事件解析（Phase 6，2026-09-09）

- 事件模型：G（时间，自有值）锚定=事件首行，其后到下一个 G 自有行之间带 J 的行并入同一事件（跨行续写；I 台数取首行）；真实文件共 **144** 事件（内部含「双发」101 + 外部 43，与决策 15 口径一致）。
- J 编号单元格（BorrowCellParser，§十四/§十五）：纯编号列表、`编号（注释）`、括号开头列表、嵌套异常（`11612（11369（带拖布轮）`）尽力提取编号并标 REVIEW；"无编号"按 I 台数理解批量；括号注释如 `2026.9.4入南库` 可可靠解析出归还日期（ReturnDate），无法可靠解析不猜（原文保留在 remark）。
- 本阶段只解析为结构化 BorrowEvent（含 raw 原文、needs_review），**不写库不改状态**；写 flow_record / borrow_record、状态推导、Preview/Review 分别在 Phase 7/9/10。

### v1.1 设备最终状态推导（Phase 7，2026-09-09）

- 推导输入：F 设备全集（编号每 token 一台 / 无编号逐台）+ J BorrowEvents（含块上下文 name/model）。
- 匹配规则：事件编号**优先按事件所在块**（BorrowEvent.Name/Model）命中设备；块内未命中时若该编号全局仅一个块出现过 → 跨块唯一命中；否则 REVIEW（跨块同号无法定位，W-4，不猜）。
- 状态建议（决策18 §十九/§二十）：导入默认全部 IN_STOCK；设备最后一条借出事件**带可靠归还日期（入南库/回库线索）** → 已回库保持 IN_STOCK；**无归还证据** → 「疑似在借」（SUSPECTED，供 Preview 勾选后再置 BORROWED，绝不自动设置、绝不凭空制造 RETURN）；缺日/事件需人工 → REVIEW。
- 输出 `ParseResult.Derived`（DerivationReport：设备数/疑似数/疑似清单/REVIEW/匹配/未匹配/归还线索计数）。真实文件推导：设备 2147、疑似在借 352、REVIEW 71、未匹配 1（R119 跨块 0518）、归还线索 2（R334/R340 入南库）。

### v1.1 清空重导 / 真实 Excel 终验（Phase 10，2026-09-09）

- `service.ClearImportData`：单事务清空业务数据（equipment / flow_record / borrow_record / import_batch），**保留字典（category/team/borrower）、settings、audit 历史**（历史留痕永不清除）。
- `POST /api/import/reset`（危险操作，决策18⑤/铁律5）：需 `confirm:true`；执行顺序 = 统计现有规模 → **自动备份** → 单事务清空 → `IMPORT_RESET` audit。空库幂等（提示无需清空）。
- 前端 ImportPage 新增「清空重导（危险）」入口：二次确认弹窗（明示自动备份 + 清空范围 + 字典保留 + 可从备份恢复），成功后清空预览状态可重新上传。
- 真实 Excel 端到端验收（测试）：非空库 → reset(确认) → parse → REVIEW 全清点 → run 全量导入 **2147 台**；REVIEW 未清点 → 422 门禁。

### v1.1 数据对账 Reconciliation（Phase 11，2026-09-09）

- `importer.Reconcile(db, res)`：以解析结果 source_hash 关联已导入批次，将 Excel 可导入设备（source_key 全集）与数据库该批次设备**逐台比对**：
  - 总量：Excel 可导入台数 vs 数据库批次台数；
  - 缺失（Excel 有/DB 无）与多出（DB 有/Excel 无）逐台列出（显示编号/名称/型号/来源行/内部码）；
  - 有编号/无编号台数、同号多台组数（Excel/DB 双侧）、历史借出未匹配（Derived）。
  - 任何差异 → FAIL 并列出；全等 → PASS。
- `POST /api/import/reconcile {parse_id}`：run 后保留解析会话（仅清理上传文件）供对账；无批次/会话过期返回明确提示。
