# Excel 导入规则 import-rules.md

> 文档编号：DSH-EQ-IM · 版本：v0.1.0-phase0 · 日期：2026-09-07
> 输入：`设备借出总账.xlsx`（原文件，**导入过程只读**）；结构详见 `docs/data-analysis.md`。
> 目标：把 Excel 结构化数据安全导入 SQLite，禁止未校验直写、禁止猜测字段含义（W-1…W-15 未确认前不得放行对应数据）。

---

## 1. 导入范围与策略（分两层，防错优先）

### Tier 1：设备台账（必做，安全）
仅导入"设备主块（A–F）"→ category/equipment（每块按 D 数量生成实体）。

### Tier 2：借出历史（受限；W-2 已答复，2026-09-08 决策 15）

Excel 无归还列 → 不能从文件判定"当前哪些设备仍在外"。**用户已确认采用方案 A**：

- 方案 A（已定）：Tier 1 只建台账（全部初始"在库"+IMPORT_INIT）；借出历史**不自动导入当前状态**，由用户根据实际在借情况在系统内**手动补录**外借/流转，保真不造假；
- 方案 B / 方案 C（已弃，不再作为导入选项；如未来需要历史时间线还原可另行评估）。

> 状态：Tier 1 为本阶段（Phase 2）实现范围；Tier 2 无自动导入。

## 2. 解析规则（块级）

1. 定位表头 R2（列 A–K 语义固定）；R1/R467/空行/合并间隙行跳过。
2. **设备块识别**：以 B（名称）纵向合并区间或单行实体为块边界（结合 A 合并区与 B/C 合并区间；实现在导入器内按"B 单元格非空行"起块、直到下一块首行）。
3. 块内字段回填：类别（A 合并值）、名称（B）、型号（C）、D/E 取块首（D 为合并总台数，E 为财务段；块内如有多个 E 段则累加做校验）。
4. F（编号）：按空白（空格/换行/全角空格）切分为 token 清单；逐 token trim；
   - `无编号` → 整块无编号设备（数量=D，不产编号行）；
   - token 含字母/数字混合 → 视为真实编号原样保留（不转数字）；
   - token 含括号注释（如 R165/R197/R198/R199）→ 剥离注释保留编号本体，注释存入该设备 remark（W-7 默认）；
   - 首尾多余空白丢弃；行尾续写跨行合并为块的完整清单。
5. G/H/I/J/K（借出事件，Tier 2 使用）：同一行 G 非空=事件首行；I 台数、J 编号 token（规则同 F）；事件跨行续写时（本行 I 与 J 计数不一致但下行 J 续写）按"从该行起直到下一事件首行前的连续 J 行"合并为一个事件。
6. 日期解析：`YYYY.M.D`（M/D 可为 1~2 位）统一为 SQLite ISO；`2018.4`（W-11）缺日 → 报告 WARN 并默认补 1 日或整行待确认（默认补 1 日仅当用户勾选）。
7. 文字规范化：入库字段 trim；B/C 全半角括号保留原文；不主动归并近义名称（W-9）。

## 3. 字典构建

- 类别（A）：识别 4 个明确类别（裁剪设备/缝纫设备/包装设备/技术设备）→ 自动建 category；`买发网厂/买华诺/买针织厂`（R344–R380）与 R429–466 无类别行 → **按 W-1 结果处理**（未确认前归类为待确认类别并标记，绝不静默归并）。
- 外借方（H，19 个名称）：**W-5 已定（决策 15）** —— 名称含「双发」的 4 个内部单位（莒县双发、双发分厂（龙山贸易/华锦/夏津））属**内部调拨**，建 **team（内部单位）字典**而非 borrower；其余 15 个公司建 borrower（name UNIQUE，重复命中即复用）；联系人/电话留空（源无）。Tier 1 不自动落这两个字典（初始全在库，由后续操作按需创建）。
- 班组/内部单位：Tier 1 不自动创建（W-2 方案 A：初始均在库）。
- 无编号设备：equipment_no=NULL，生成 `internal_code=EQ-%06d`（决策 6 与章程 §14：不伪造财务编号）。

## 4. 校验矩阵（逐块/逐行执行，阻断或警告）

> v1.1（决策 18，2026-09-09）已修订 V3/V10 语义：重复编号=同号多台真机（WARN+展开，不再 BLOCK）；描述文本=情况 B（自动转无编号+原文备注，不再 BLOCK）；无法自动判断=情况 C（REVIEW，人工确认前该组不导入，绝不静默丢弃）。

| # | 校验 | 级别 | 处理 |
|---|---|---|---|
| V1 | D 与块内展开设备数（编号 token + 无编号台数）一致 | BLOCK | 报告差异明细（块名+行号+差异值，§十二） |
| V2 | E 分段合计 == D | WARN | 不一致仅报告（E 为财务口径，W-13） |
| V3 | 块内 F 出现重复编号 | WARN | 按同号多台真机展开（每 token 一台，equipment_seq 区分）；如需合并人工核对 |
| V4 | 全局 equipment_no 撞号（跨块同号，如 001–023） | ~~BLOCK~~ 废弃 | equipment_no 非唯一键（决策 18）；跨组各自独立 |
| V5 | 编号疑似 O/0（含 O 的编号） | WARN | 列出（R317/R394），建议人工确认 |
| V6 | 编号列为空但台账数量>0 | WARN | 按无编号处理并报告（名称必填仍 BLOCK） |
| V7 | 借出事件 J 编号不在本块 F 内 | WARN | 列出来源块外编号（W-10） |
| V8 | 借出事件 I 台数与 J token 数不等（非续写情形） | BLOCK/WARN | 续写合并后仍不等 → BLOCK |
| V9 | 日期异常（格式不符/缺日/未来日期） | WARN | 列出；按 §2.6 规则处理 |
| V10 | F 列内容分类：描述文本（情况B）/无法判断（情况C） | WARN/REVIEW | 描述→无编号+原文入备注；REVIEW→人工确认后该组才导入 |

> 所有 BLOCK 项未解除前**禁止写库**；WARN 项可预览并在报告中高亮，用户可勾选"接受后导入"。

## 5. 导入流程（UI 五步，章程 Phase 2）

```text
1) 选择 Excel（本地文件，仅读）
2) 解析（后台执行 §2/§3）
3) 数据预览（块列表/实体样例/字典预览；差异高亮）
4) 校验报告（V1–V10 结果 + 异常明细表，可导出）
5) 用户确认（危险操作二次确认）→ 单事务写入 SQLite → 导入报告
```

**导入报告指标**（章程/主 Prompt 要求）：总记录 / 成功 / 跳过 / 重复 / 异常 / 无编号，另附：
- 设备块总数、设备实体总数（按 D）、类别数、外借方数；
- BLOCK/WARN 明细（可导出 Excel/CSV）；
- 生成的 internal_code 段（EQ-000001…）。

## 6. 初始现状固化（决策 7）

- Tier 1 导入成功后，为每条设备写一条 `transaction(action=IMPORT_INIT, from=初始, to=IN_STOCK, occurred_at=导入日或Excel时间(推荐导入日统一), operator=系统导入, remark=来源行号Rxx)` —— 历史从第一天完整可追溯；
- 若按 W-2 方案 C 提供"当前在借清单"，另为对应设备写 `BORROW` 事件（借出时间用清单日期）；
- **幂等与覆盖防护**：仅允许"空库"或"已导入同文件版本号"前提下执行全量导入；已有业务数据时禁止覆盖导入（数据安全铁律 6/危险操作确认）；如确需重导，走"备份→清空(二次确认+audit)→导入"专门流程（Phase 2 设计）。

## 7. 导入实现约束（技术）

- Go 侧 xlsx 解析：锁定 Go1.20 兼容版本 excelize（构建矩阵验证）；大文件(≤10MB)无压力；
- 解析不依赖 Excel 安装、不联网；
- 入库使用单事务；任何 BLOCK 即整体中止并回滚，保证无脏数据；
- 错误信息给出**行号 + 块名 + 具体值**，便于用户回表核对。
